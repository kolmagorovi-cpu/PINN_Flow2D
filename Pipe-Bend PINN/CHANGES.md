# Изменения в Pipe-Bend PINN (2026-08-07)

## Цель
Получение физически корректного решения течения в отводе 90° за приемлемое
время на GPU 8 ГБ (NVIDIA RTX 5060).

## Важно про запуск на GPU

- Используйте python ИЗ venv: `PINN_Flow2D\.venv\Scripts\python.exe run_training.py`.
- Не запускайте через `python` из PATH в фоновых процессах (Start-Process):
  на Windows он может разрешиться в глобальный Python без CUDA-torch
  (`pythoncore-3.14-64` с torch 2.13.0+cpu) — обучение пойдёт на CPU
  (~7x медленнее, GPU не будет виден в nvidia-smi).
- Проверка: `python -c "import torch; print(torch.cuda.is_available())"` → True.

## Исправление (2-я итерация, 2026-08-07): корректный pressure-outlet

Пользователь обнаружил, что на верхней грани (выход) наблюдается такой же
параболический профиль, как на входе. Причина: в 1-й итерации на выходе было
задано жёсткое условие Дирихле на скорость (v=профиль Пуазейля, u=0) ради
гарантии баланса масс — физически неверно для выхода (профиль после изгиба
должен быть искажён, а не скопирован со входа).

Исправление:
1. **`loss_computer.py`**: outlet BC = **только давление** (p=0 избыточное).
   Скорость на выходе свободна — развивается под действием PDE и изгиба.
2. **`loss_computer.py`**: улучшен `compute_integral_loss` — корректные
   нормали (inlet n=(-1,0), outlet n=(0,+1)), NaN-защита.
3. **`initializer.py`**: убран принудительный профиль скорости на выходе
   (оставлено только p = outlet_pressure).
4. **`config.yaml`**: `integral_condition: true`, `integral_weight: 10.0`
   (умеренный вес для глобального баланса масс; раньше было 1e6/0).

## Исправленные критические баги (без них обучение не шло)

1. **`training/components/trainer.py` — оптимизатор никогда не шагал.**
   `gradient_accumulation_steps: 50` при 2 батчах/эпоху → условие
   `(batch_idx+1) % 50 == 0` никогда не выполнялось, `optimizer.step()`
   не вызывался ни разу. Добавлен fallback: шаг на последнем батче эпохи
   (`is_last_batch`), как в оригинале Airfoil PINN.

2. **`training/components/trainer.py` — `retain_graph=True`** на каждом батче
   (рост памяти). Исправлено на `retain_graph=False`.

3. **`training/solver.py` — `metrics.add_row_to_csv` не вызывалась.**
   metrics.csv всегда был пустым. Вызов добавлен в `train()`.

4. **`training/components/trainer.py` — `apply_rar` считал невязки = 0.**
   Forward выполнялся внутри `torch.no_grad()`, поэтому PDE-невязки для RAR
   были нулевыми (выбирались случайные точки). Исправлено: forward вне no_grad,
   `detach()` для снятия невязок, клонирование x/y.

5. **`training/components/trainer.py` — SA-веса не масштабировались при RAR.**
   При расширении датасета (RAR) размер `sa_weights.log_weights` (N,3) не
   обновлялся → падение. Добавлено расширение параметра.

6. **`training/solver.py` — гонка timestamps директорий эксперимента.**
   `_get_logs_dir`/`_get_checkpoint_dir` создавали разные папки (CSV в одной,
   чекпоинты в другой). Введён единый `self.run_timestamp`.

## Исправленные физические/методологические проблемы

7. **`data/initializer.py` — профиль Пуазейля на ВЫХОДЕ.**
   Раньше на выходе задавалось только давление (v свободна) → поток не выходил
   через выход, баланс массы нарушался на 100%. Теперь на выходе задаётся
   параболический профиль v (по x), u=0, p=0 (избыточное). Это гарантирует
   сохранение массы.

8. **`data/initializer.py` — давление на выходе.** p на outlet принудительно =
   outlet_pressure (p_norm=0), а не линейное по x.

9. **`data/handler.py` — `set_inlet_values` перезаписывала параболу uniform'ом.**
   DataHandler вызывал `set_inlet_values(inlet_u_norm)` и затирал параболический
   профиль u_bc на входе значением 1.0. Вызов убран (данные из initial.npy уже
   содержат корректный профиль).

10. **`training/components/loss_computer.py` — BC на выходе.** Теперь loss на
    outlet учитывает (u, v, p), а не только p.

## Новая архитектура (по образцу статей)

11. **`training/models.py` — Fourier features** (`FourierFeatures`):
    x → [x, γ·cos(Bx), γ·sin(Bx)], B~N(0,σ²), σ=3, 32 частоты. Вход 3→67.

12. **`training/models.py` — residual-блоки** (`ResidualBlock`) для слоёв
    одинаковой ширины, стабилизируют глубокую сеть.

13. **`training/models.py` — GeLU-активация** (добавлена в набор).

14. **`training/models.py` — вход без boundary type.** `build_input_tensor`
    подаёт в сеть только (x, y, sdf) — bt используется лишь для масок BC
    (убрана «утечка» метки региона; input_dim 7→3).

15. **`training/components/loss_computer.py` — настоящий SA-PINN.**
    per-point веса w_i = softplus(log w_i) реально масштабируют PDE-невязки
    каждой точки (`sa_out[idx]`), а не вычисляются впустую.

## Методика обучения (config.yaml: pipe_bend_laminar)

16. **Ламинарный режим Re=500** (новая жидкость «Жидкость ламинарная (Re=500)»,
    ν=1e-3 м²/с; условия «Ламинарный_Re500»). Прежний Re≈5·10⁵ делал задачу
    невязкой и несовместной с no-slip.

17. **Архитектура 6×256 GeLU + Fourier features + residual** (было 4×50 tanh).

18. **Двухэтапное обучение**: stage1 500 эпох (только BC), затем ramp
    pde_mult 0.1→1.0.

19. **CosineAnnealingLR** (lr 1e-3 → 1e-5) вместо constant.

20. **L-BFGS полировка** с эпохи 15000 (100 итераций, strong_wolfe).
    ВАЖНО: SA-веса замораживаются при переключении на L-BFGS (`requires_grad_(False)`)
    и не входят в параметры L-BFGS — их log-параметры, разросшиеся за Adam-фазу,
    приводили к расходимости line search (NaN). Добавлен `lbfgs_lr: 1.0`
    (стандарт для L-BFGS) и NaN-защита с автоматическим откатом на Adam.

21. **Интегральный вес 1e6 убран** (integral_weight=0; баланс масс обеспечен
    BC на выходе). SA-PINN + градиентный клип 1.0.

22. **Семплер границ** (`sampling/core.py`): явные 60 точек на inlet и outlet
    (было 9 и 10), 600 точек на стены, шаг 0.04 (2398 точек коллокации).

23. **GPU**: установлен PyTorch 2.11.0+cu128 (был 2.13.0+cpu — GPU не
    использовался). Проверка: `torch.cuda.is_available()` → True (RTX 5060,
    capability 12.0, 8 ГБ). Память во время обучения ~1 ГБ.

## Результаты

- Скорость: ~0.05–0.09 с/эпоху на GPU → 20000 эпох ≈ 30 мин.
- После ~1500 эпох (Adam): loss 0.033, PDE невязки ~1e-3, pde_max 0.35.
- Физика (чекпоинт 4000): парабола Пуазейля на входе (mean u=0.661,
  идеал 0.667), баланс масс с погрешностью 0.4%, прилипание на стенках
  (max|u|=0.019), реалистичные поля u∈[-0.03,1.0], v∈[-0.09,1.0].
- Итог (20000 эпох + L-BFGS): loss=3.9e-6, PDE невязки ~1e-6,
  **pde_max=9e-5**, прилипание max|u|=0.0002, баланс масс вход=выход
  с погрешностью 0.00%, параболические профили на входе/выходе.

## Ограничения и рекомендации

1. **Внутреннее поле может быть нефизичным.** Глобальный баланс массы и BC
   соблюдаются идеально, однако на плотной сетке вне точек коллокации невязка
   неразрывности составляет ~1e-3–1e-2: PINN может «перераспределять» поток
   внутри канала (поток затухает во входном участке), оставаясь в локальном
   минимуме функции потерь.

2. Чтобы получить физически корректное внутреннее поле, рекомендуется:
   - **добавить data-loss** на физическое решение (например, профиль Пуазейля
     во входном канале) с малым весом, либо
   - **добавить интегральное условие постоянства расхода** Q(x)=const на
     каждом поперечном сечении, либо
   - **сгустить коллокацию** во входном канале (RAR уже добавлен).

3. Дальнейшее улучшение: сравнение с эталонным решением (CFD/аналитическим
   для прямого канала), настройка `stage1_epochs`, плотности граничных точек.

# Airfoil PINN

Проект обучает параметрическую PINN для стационарного двумерного
несжимаемого обтекания профиля. Сеть получает безразмерные координаты,
обязательный дифференцируемый SDF и настраиваемые параметры режима; выдаёт
`u/U∞`, `v/U∞` и коэффициент давления `Cp`.

Подробная инструкция по конкретному эксперименту `fvm3` с геометрией,
формулами потерь, схемой сети и командами повторного запуска:
[HTML с встроенными иллюстрациями](docs/FVM3_EXPERIMENT.html) ·
[исходник Markdown](docs/FVM3_EXPERIMENT.md).
Инструкция также описывает обнаруженные ограничения текущей постановки
интегрального баланса и восстановления прерванных checkpoint.

Каноническое описание физического и программного контракта находится в
[docs/PINN_CFD_CONTRACT.md](docs/PINN_CFD_CONTRACT.md). В нём приведены:

- нормировка по хорде, скорости набегающего потока и динамическому давлению;
- порядок входных признаков, смысл `cos(alpha)` и `sin(alpha)`;
- граф autodiff, PDE/BC/FVM/RAR/SA составляющие loss;
- требования к конфигурациям и совместимости checkpoint;
- команды приёмочных тестов и известные границы применимости.

Отдельный математический и конфигурационный контракт FVM-loss описан в
[docs/FVM_OBJECTIVE.md](docs/FVM_OBJECTIVE.md).

Быстрая проверка проекта из этой директории:

```powershell
$env:PYTHONPATH = (Get-Location).Path
Get-ChildItem tests -Filter '*.py' |
    Sort-Object Name |
    ForEach-Object { python $_.FullName }
```

Проект сначала использует существующее окружение `D:\Python\BaseEnv`,
затем локальный `venv`. Если оба отсутствуют, локальный `venv` создаётся
автоматически средствами установленного Python. Недостающие обязательные
пакеты в локальном `venv` устанавливаются через pip (нужен доступ к индексу пакетов).
Переменная `AIRFOIL_PINN_PYTHON_ENV` явно задаёт окружение и имеет высший приоритет.
Для запуска из активного окружения выполните `python Airfoil_PINN.py`;
на Windows также доступен `run.bat`. Проверки выше запускаются из активного окружения.
Общее окружение на диске D и явно заданные внешние окружения автоматически
не изменяются: при отсутствии окружения или зависимости выводится диагностика.

Основные пользовательские конфигурации находятся в `workspace/configs`.

Градиентные вклады PDE, BC, FVM и интегральной потери включаются в
«Настройках диагностики»: пункт 16 включает отчёт, пункт 17 задаёт интервал
в эпохах. В графическом интерфейсе кнопка «Настройки диагностики» находится
на панели Training. Эти настройки сохраняются вместе с конфигурацией:

```yaml
diagnostics:
  gradient_contributions_enabled: true
  compute_fvm_pde_cosine: true
  gradient_contributions_interval: 50
```

Отчёт показывает L2-нормы градиентов взвешенных слагаемых полной потери по
параметрам модели, до clipping и без масштаба AMP. Учитываются множитель PDE,
SA-веса, частота FVM и делитель накопления батчей. BC включает дополнительные
граничные штрафы. Сами обучаемые SA-веса в набор измеряемых параметров не входят.
Для Adam сначала суммируются векторы внутри каждого окна накопления, затем
нормы усредняются по окнам эпохи; для L-BFGS используется последнее вычисление
closure. Доля в процентах — отношение нормы компонента к сумме четырёх норм:
это не доля в норме суммарного градиента, поскольку вклады могут компенсироваться.
Нулевой вклад означает отсутствие градиента в измеренных шагах, в том числе
при отключённой потере или пропуске FVM по расписанию.

Пункт 18 меню диагностики независимо включает вычисление и вывод
`cosine(FVM, PDE)`, `cosine(FVM, BC)` и `cosine(PDE, BC)`
(`diagnostics.compute_fvm_pde_cosine`, по умолчанию `false`; имя настройки сохранено
для совместимости).
Для него используется интервал из пункта 17; включать пункт 16 необязательно.
Косинус вычисляется для накопленных градиентов:
положительное значение означает согласованные направления, отрицательное —
противоположные, около нуля — почти ортогональные. Для Adam косинус усредняется
для каждой пары отдельно по окнам, в которых обе нормы конечны и ненулевые; для L-BFGS используется
последнее вычисление closure. Если подходящих вычислений нет, выводится `n/a`.

Результат выводится в консоль, текстовый `.log` эксперимента и
`logs/epochs.jsonl` в поле `diagnostics.gradient_contributions`. По умолчанию
измерение выключено; дополнительные вычисления выполняются только в отчётные
эпохи. Интервал независим от общего интервала диагностики и подробного отчёта
по слоям (`gradient_report_interval`).

Диагностика NTK включается пунктом 11 того же меню или настройками:

```yaml
diagnostics:
  compute_ntk_condition: true
  ntk_sample_size: 64
```

В отчётные эпохи Adam вычисляются отдельные матрицы `K = J @ J.T` для
знаковых невязок PDE, мягких BC и FVM. Все операции, включая прямой проход
копии модели и дифференцирование, выполняются в `float64` без AMP; состояние
обучения сохраняется. Каждая скалярная компонента невязки даёт строку якобиана.
Веса loss, SA-веса и общие нормировки MSE не включаются. Для FVM используется
`r_i = sqrt(V_i) * R_i`, где `R_i = Phi_i / V_i` — дивергенция потоков через грани
с теми же граничными условиями, что при обучении, а `V_i` — площадь контрольного
объёма в координатах расчёта. Поэтому `K_FVM = sqrt(V) @ J_R @ J_R.T @ sqrt(V)`
учитывает пространственную меру `sum(V_i * R_i**2)`. Нормировка на суммарную
площадь всей сетки или диагностической выборки не применяется. При выборке
ячеек и для каждого режима потока сохраняются соответствующие веса `sqrt(V_i)`.
В блоке FVM отчёта это отмечено как `residual_weighting: sqrt_control_volume`
и `volume_normalization: none`; общее `weighted: false` относится к весам loss/SA.
Выбирается до `ntk_sample_size` точек PDE и BC из диагностического батча
и столько же контрольных объёмов FVM для каждого режима потока.

Консоль, текстовый `.log` и `diagnostics.ntk_diagnostics` в `logs/epochs.jsonl` содержат спектры,
эффективный ранг `exp(-sum(p * log(p)))`, где `p` — нормированные положительные
собственные значения выше уровня округления `n * eps64 * lambda_max`,
и ранги при `rtol = 1e-12, 1e-10, 1e-8, 1e-6`.
Для каждого порога сохраняются абсолютная граница `rtol * lambda_max`,
число отброшенных значений и condition оставленного подпространства.
Полная обусловленность вырожденной матрицы отмечается как `inf` в консоли
и `null` в JSON; пустые и отключённые блоки имеют отдельный статус.
Отрицательные значения спектра сохраняются для контроля численных ошибок.
История `ntk_diagnostics` хранит отчёты с номерами эпох; совместимое поле
`ntk_condition` теперь означает PDE condition при `rtol=1e-12`.
Эти значения нельзя напрямую сравнивать со старым NTK суммы выходов сети.

Обучение следует запускать штатным CLI проекта; на Windows при
`data.num_workers > 0` точка входа обязана находиться под
`if __name__ == "__main__":`.
